# ML Empowerment Build Challenge 3.0 提交清单

## 截止时间与资格

交接材料给出的官方截止时间是 **2026 年 10 月 10 日 21:00 PDT**。按该时区换算：

- 日本时间：**2026 年 10 月 11 日 13:00 JST**。
- 北京时间：**2026 年 10 月 11 日 12:00 CST**。
- UTC：2026 年 10 月 11 日 04:00。

提交当天以比赛页面显示的实际截止时间为准，建议至少提前一天完成。交接材料中的“北京时间 13:00”与 PDT 换算相差一小时，应使用上面的换算值。

参赛条件据交接材料为高中或大学学生、个人或不超过 5 人团队、全球开放。**由参赛者本人确认学生身份、团队资格及现有项目是否符合比赛的开发时间和复用规则**，如实说明赛前已完成的工作；这些信息没有在本材料中代填。

- [ ] 准备粘贴用的 `submission-en.md`。
- [ ] 检查 `shots/` 下的英文实机截图，并阅读 `shots/README.md`。
- [ ] 如录制视频，按 `项目介绍视频文案.md` 录制和剪辑；检查实际画面与旁白一致。文案文件本身不是可上传的演示视频。

- [ ] 准备真实姓名或公开显示名、学校及团队成员信息。不要把本地应用账号当作 Devpost 团队资料。

## 手把手操作

1. **注册或登录 Devpost。** 打开 [Devpost](https://devpost.com/)，由你本人创建或登录账号，完成平台要求的邮箱验证与个人信息。
2. **找到并加入比赛。** 在 Devpost 搜索 `ML Empowerment Build Challenge 3.0`；核对名称、主办方、截止时间和完整规则，再点 `Join hackathon` 或页面对应入口。遇到参赛资格、项目复用或开发时间要求，先按实际情况确认。
3. **创建项目提交。** 从比赛页面进入 `Start a submission`、`Submit project` 或实际显示的入口。若已有项目草稿，打开该草稿继续，避免重复创建。
4. **填标题与简介。** Project name 填 `InspirationSpace`。Tagline 可用 `Turn passing thoughts into considered views.`；若有更长的短描述栏，使用 `submission-en.md` 的 Tagline 段落。完整标题可用 `InspirationSpace — Turn passing thoughts into considered views.`，超出字段长度时保留项目名，把宣传语移到简介。
5. **填项目正文。** 按 `submission-en.md` 粘贴 Problem、Solution、Key Features、Tech、Target Users 和 Social Impact Statement。如果页面只有一个正文框，按原有标题合并粘贴；如果页面另设 Inspiration、What it does、How we built it 等栏，将 Problem/Solution/Tech 分别对应填入。不要填写未发生的挑战、成果、测试或开发经历。
6. **填写 Built with。** 按平台可用标签填写 Python、FastAPI、SQLAlchemy、SQLite、React、Vite、Tailwind CSS、pywebview；实际模型/服务商名称以你配置和使用的情况为准。OpenAI 兼容协议不代表一定使用了 OpenAI 模型。
7. **上传功能演示。** 从 `shots/` 上传首页、Whetstone、Anthology、登录页截图。优先把 Whetstone 放在展示顺序靠前的位置。图片说明按 `shots/README.md` 中的英文说明填写。平台若要求视频链接而不是视频文件，将录制成片上传到你选择的平台，再粘贴可公开访问或可凭链接访问的 URL。
8. **填写仓库与演示链接。** Code repository 填 `https://github.com/Bob-Heng/inspiration-space`。可在 Additional links 填仓库 Releases 页作为 Windows 安装包入口。`localhost:8000` 是本机地址，不能充当评委可访问的线上演示链接。
9. **填写团队成员。** 添加本人及实际共同开发的成员，按页面要求邀请或关联账号。学校、角色、贡献等信息由你核对后填写。
10. **预览并保存。** 检查英文正文、截图顺序、图片清晰度、链接可访问性，以及任何必填项。声明真实开发时间和赛前资产；核对比赛要求的许可、授权或其他勾选项。
11. **由你点击正式提交。** 使用页面实际显示的 `Submit` 或 `Submit project` 按钮。草稿保存不等于提交。查看项目状态、确认页或确认邮件，并保留凭据。
12. **检查提交后的公开页面。** 再次打开项目页，确认文字、截图、视频和仓库链接正确。允许修改时，按页面规则完成修正，并确认仍是已提交状态。

## 完成标准

- [ ] 项目归属正确比赛，状态明确为已提交。
- [ ] 至少一个真实功能演示文件可查看；视频若使用，链接可访问且有英文字幕或旁白。
- [ ] 正文、技术标签与实际实现一致，没有虚构用户数、学习成效或参赛经历。
- [ ] 团队资料与参赛资格由本人确认。
- [ ] 已保存提交凭据和项目页 URL。

本任务准备材料及仓库展示。Devpost 注册、登录、团队资料确认与最终提交均由用户本人完成。
