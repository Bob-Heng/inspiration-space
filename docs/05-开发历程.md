# 05 开发历程（一阶段存档）

> 存档：一阶段（MVP-1~5）已于 2026-10 全部完成验收，此后转入边用边改模式，不再按 TASK 拆分（见 04 G11）。本文件仅作历史参考，不再更新。

## 一阶段 MVP → TASK 拆解

每个 TASK 设计为可在一个上下文窗口内独立完成：目标单一、输入明确、验收可测。前置依赖按编号顺序满足。

### MVP-1：项目骨架 + 登录 + 灵感录入（待审队列）

| TASK | 内容 | 验收标准 |
|---|---|---|
| TASK-001 | 初始化项目结构（backend/ frontend/ scripts/ docs/），依赖清单，启动脚本 | 前后端分别一条命令可启动空壳 |
| TASK-002 | SQLite schema + SQLAlchemy 模型：users / inspirations / viewpoints / viewpoint_relations / review_sessions / review_messages / review_decisions / ai_calls（job_runs 留待后续阶段） | 建库脚本可重复执行；字段覆盖 docs/02 的分层、四标签族、状态 |
| TASK-003 | 领域逻辑：灵感编号、观点状态机（采纳/悬置/否定）+ 状态机单元测试 | 非法状态转换被拒绝；测试通过 |
| TASK-004 | 密码登录 + Session + 受保护路由 | 未登录访问 API 返回 401；登录后可访问 |
| TASK-005 | 灵感 CRUD API（录入、列表、编辑、删除；录入即入队、自动编号） | REST 全通；Swagger 文档可查 |
| TASK-006 | 前端应用外壳：最小登录页 + 路由保护 + 首页承载"灵感录入与队列"组件（录入/列表/编辑/删除；组件后续复用于审议页，不设独立灵感页） | 界面完成"登录 → 录入 → 队列出现"闭环 |

### MVP-2：AI Service + 审议分析

| TASK | 内容 | 验收标准 |
|---|---|---|
| TASK-007 | LLMProvider 抽象层 + New API Provider（base_url/key 走环境变量，启动时探活） | 网关未启动时报错信息明确；简单对话调用成功 |
| TASK-008 | 结构化输出：JSON Schema 定义 + 校验 + ai_calls 全量留痕（model/prompt_version/input/output） | 非法 JSON/缺字段被拒绝并留痕 |
| TASK-009 | 审议分析接口：输入灵感 + 观点库快照，输出采纳理由/最强反对理由/分层与四标签建议/相近冲突关系/第一轮疑问 | 输出通过 Schema 校验；引用的观点 id 真实存在 |

### MVP-3：审议工作台

| TASK | 内容 | 验收标准 |
|---|---|---|
| TASK-010 | 审议会话 API：开始会话（关联灵感）、追加消息、持久化 | 会话与消息落库，可断点续聊 |
| TASK-011 | 审议决策 API：采纳 / 修改后采纳 / 否定 / 暂缓；采纳时事务完成"建观点 + 建关系 + 灵感出队 + 记决策" | 任一步失败整体回滚；暂缓不产生新终态 |
| TASK-012 | 审议工作台前端（三栏：队列 / 灵感+分析+对话 / 关联观点与标签建议；底部决策栏） | 完成一条灵感"分析→讨论→采纳"全流程 |

### MVP-4：观点库

| TASK | 内容 | 验收标准 |
|---|---|---|
| TASK-013 | 观点查询/筛选 API（道法术 / 状态 / 四标签族 / 日期） | 组合筛选结果正确 |
| TASK-014 | 观点关系 API：相近/冲突建立与解除；冲突双方自动转悬置并互记编号；合并与拆分 | 冲突联动正确；合并保留双方原文 |
| TASK-015 | 观点库前端（表格/卡片 + 多维筛选 + 关系展示） | 筛选与关系可视化可用 |
| TASK-016 | 分类观点视图（道/法/术，排除否定，悬置保留标记，按日期排序） | 与数据库直查结果一致 |

### MVP-5：迁移 + 导入导出

| TASK | 内容 | 验收标准 |
|---|---|---|
| TASK-017 | 原系统 Docx 解析器 + 历史数据迁移脚本（28 条待审 + 5 条原始观点，规则见 docs/03） | 迁移后条数、日期、标签位与盘点一致；游离文本独立成条 |
| TASK-018 | 外部 docx 导入功能：上传 → AI 拆解归纳（只切割不改写、保留日期）→ 入待审队列 | 用旧灵感记录 docx 实测，拆解结果人工抽查可用 |
| TASK-019 | 观点库 Docx 导出（原始观点 + 分类观点三文档，沿用原格式） | 导出文件与原系统格式兼容 |
| TASK-020 | 全链路集成验证：录入 → 审议 → 观点库 → 分类视图 → 导出 | 端到端走通，迁移数据在内 |

## 上下文窗口分配与工时估算

基准：TASK-001（纯脚手架）实际耗时 12 分钟，上下文消耗极低。以下估算以此为锚；涉及真实 LLM 调用的 TASK 受网关与模型速度影响，波动最大。

**原则：按 MVP 分配上下文窗口**（同一 MVP 内文件耦合紧、共享上下文收益大）；每完成一个 TASK 立即 git commit 一次，形成细粒度回滚点；若窗口内出现上下文紧张，后端 TASK 与前端 TASK 之间是天然的拆分点。

| 窗口 | 包含 TASK | 估算工时 | 人工前置事项 |
|---|---|---|---|
| ✅ TASK-001 | 项目骨架 | 实际 12 min | 已完成 |
| ✅ 窗口 1 · MVP-1 | TASK-002~006（schema → 状态机 → 登录 → 灵感 CRUD API → 前端录入组件） | 实际 22 min | 已完成并通过验收 |
| ✅ 窗口 2 · MVP-2 | TASK-007~009（LLMProvider+NewAPI → Schema 校验留痕 → 审议分析接口） | 实际 20 min | 已完成并通过验收 |
| ✅ 窗口 3 · MVP-3 | TASK-010~012（会话 API → 决策事务 → 审议工作台前端） | 实际 32 min | 已完成并通过验收（用户已真实审议一条灵感并采纳入库） |
| ✅ 窗口 4 · MVP-4 | TASK-013~016 + 附带修复时间戳 UTC/本地混用 | 实际 25 min | 已完成并通过验收 |
| ✅ 窗口 5 · MVP-5 | TASK-017~020（Docx 迁移 → AI 拆解导入 → 导出 → 端到端验证） | 实际约 2 h（含中断） | 已完成并通过验收 |

> ⚠️ 验收勘误（2026-09-27）：灵感 #2"水能载舟，亦能覆舟。"系**用户本人主动删除**，并非 MVP-5 窗口误删。验收时曾误判为数据事故并"恢复"了该条，经用户澄清后已重新删除，库状态与用户意图一致（灵感 29 条）。教训：验收中对数据差异下结论前，先问用户，不能仅凭间接证据归因。（该教训已升格为 04 G10。）

风险标注：以上估算基于单个数据点，前端重 UI 任务（012、015）和 LLM 联调任务（009、018）最可能超时；窗口 3、4、5 若超时，按"后端 TASK 一组、前端 TASK 一组"二次拆分。
