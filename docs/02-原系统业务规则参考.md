# 02 原系统业务规则参考

> 本文件是原系统《系统规范.docx》规则的完整沉淀，供 v2 开发时理解业务语义。**它是参考，不是必须遵守的基线**：规则优先级为 用户决策 > 设计说明书 > 本文件。已被 v2 决策取代的规则在各节标注了处置方式。

## 0. 核心架构原则

**系统状态是"观点集合"的函数，不是"输入顺序"的函数。** 凡输出依赖输入顺序的操作都是锚定来源，必须消除或隔离。这是世界观"从零重建"等规则的总依据，v2 继续保留。

## 0.1 术语映射（原系统 → v2）

| 原系统 | v2 |
|---|---|
| 灵感记录（手写 docx） | 历史档案，不再对应系统内对象 |
| 待审观点（队列条目） | **灵感**（未经审议，位于待审队列） |
| 原始观点 | **观点**（完成审议，位于观点库） |
| 派生观点 | 派生观点（暂缓，随碰撞模块） |

## 1. 对象及其读写权限

| 对象 | 原系统载体 | v2 处置 |
|---|---|---|
| 灵感记录 | `灵感记录/*.docx`，系统只读 | 取消；旧文档留作历史档案 |
| 待审观点 | `观点库/待审观点.docx` | inspirations 表（即待审队列）；界面直接录入为主，docx 导入 AI 拆解为辅 |
| 原始观点 | `观点库/原始观点.docx` | viewpoints 表，一阶段核心对象 |
| 派生观点 | `观点库/派生观点.docx` | 暂缓（随碰撞模块冻结） |
| 分类观点 | `成果/分类观点/{道,法,术}.docx` | 数据库查询视图 + 按需导出 |
| 世界观 | `成果/世界观/*.docx` | 暂缓（随建构模块冻结） |

- 真正需要区分的只有"原始观点"与"派生观点"；分类观点是视图，不是知识体系本体。
- 观点系统中的内容不能反向修改其来源灵感（审议"修改后采纳"产生的是观点正文，灵感原文保留）。

## 2. 分层：道 / 法 / 术（保留）

每条观点恰好一层：

- **道**：元假设。对世界/人性的根本设定，暂不求证。
- **法**：机制规律。世界如何运转的可检验判断。
- **术**：方法策略。面对某类问题该怎么做的操作原则。

判不准时问：这句话在说"世界是什么/怎么运转"（道/法），还是"该怎么做"（术）。例子不单独分层，随观点正文收录。

## 3. 标签族（保留）

四个标签族，每族 0~1 个，组内互斥，可留空，宁缺毋滥：

| 族 | 词表 |
|---|---|
| 领域 | 政治 / 经济 / 文化 / 社会 / 科技 / 其他 |
| 圈层 | 个人 / 家庭 / 朋友 / 同事同窗 / 公众 / 其他 |
| 学科 | 哲学 / 心理学 / 经济学 / 社会学 / 历史 / 自然科学 / 计算机 / 文学艺术 / 其他 |
| 场景 | 自我管理 / 商业创业 / 投资 / 社交沟通 / 学习认知 / 文旅消费 / 其他 |

- "其他"聚集满 3 个同类即升格为新标签；词表可随用随扩。
- 标签只是视图（检索/筛选），不是结构，可随时重打；不得作为世界观的骨架。

## 4. 状态机（保留）

### 观点状态：采纳 / 悬置 / 否定

- 任何时刻发现冲突：双方均转悬置并互记编号，**不偏向先到者**。
- 冲突裁决结果三选一：一方采纳一方否定 / 双双悬置待证据 / 合并改写为新观点。
- 系统不得擅自把悬置自动改成采纳或否定。

### 派生观点状态：自动推导，不手工维护（暂缓，随碰撞模块）

```text
任一父观点 = 否定     → 失效
全部父观点 = 采纳     → 有效
其余                  → 悬置
```

状态是算出来的，不是记出来的。

## 5. 模块规则的 v2 处置

### 原模块一 · 摄取 —— ❌ 已取消（部分职责并入他处）

原规则要点：每周状态门、按摄取位置找新增灵感、只切割不改写、重合标【再现】、相近/不相近入待审队列。

v2 处置：

- **定时摄取取消**。录入改为界面直接输入（主）+ 上传 docx 由 AI 拆解归纳（辅）；
- "只切割不改写、保留日期"的原则保留，适用于 docx 导入的 AI 拆解环节；
- 相似性/再现比对职责并入审议环节的 AI 分析；
- 状态门、摄取水位、执行时间记录随模块一并废弃。

### 原模块二 · 审议 —— ✅ 保留，v2 核心

对每条待审灵感，先输出**三项分析**，缺一不可：

1. 采纳理由 **与** 反对采纳的最强理由（必须同时给出，不得只给倾向性意见）；
2. 分层（道/法/术）与四标签族建议（每组 0~1 个，宁缺毋滥）；
3. 与库中已有观点的相近/冲突关系。

之后进入讨论：AI 先提疑问（质疑、反例、边界情况）→ 用户回答 → 用户提问 → AI 回答 → 往复，直到达成共识。**讨论中不得自行落库。** 讨论内容持久化。

讨论终点只有两种：

- **采纳**（含修改后采纳——讨论中改定的措辞落实到观点正文）；写入观点库，灵感出队；
- **完全否定**（附理由），灵感出队。

未达成共识而离开时，该条留在队列中下次继续（不产生新终态）。

关系处理：

- 发现与库中观点冲突 → 双方均转悬置、互记编号；
- 相近观点经双方确认后**无损合并**：撇去重复内容直接接续，不做改写。

### 原模块三 · 碰撞 —— ⏸️ 暂缓（规则存档备查）

每月一次；三种采样（新采纳×全库 / 强制跨标签族 / 冲突观点对）选 5~10 组候选；呈现时必须同时给出"可能没有关联"的最强反对理由；未经用户确认不得落库；已产出推论的父亲组合不得重复提出；用户无时间讨论则不更新执行记录、下期重试。

### 原模块四 · 建构 —— ⏸️ 暂缓（规则存档备查）

每季度一次；**从零重建**，禁止读取历史版本正文；只用"采纳"的原始观点与"有效"的派生观点，悬置入文末清单，否定不用；结构必须由观点自己长出来，分层与标签不得作骨架；缺环留空标【此处缺环】；未解决冲突列入"未决张力"清单；每次生成不可变新版本，旧版永久保留。

### 原附加 · 分类观点生成 —— ✅ 保留，改为查询视图

合并原始观点与派生观点，按道/法/术分类：否定与失效不列入，悬置保留标记；类内按观点日期排序。v2 中为数据库实时查询视图，导出时临时生成 Docx。

### 原附加 · 执行检查 —— ❌ 已取消

原为补救定时任务漏执行而设。v2 一阶段无定时任务，该模块无存在必要；后续碰撞/世界观上线时再按 job_runs 重新设计。

## 6. 条目格式（迁移解析依据）

- 原始观点：`序号.[日期][分层][领域/圈层/学科/场景]正文（含例子）`
- 派生观点：`序号.[日期][父：xx/xx][分层][领域/圈层/学科/场景]正文`
- 待审队列条目：`队列序号.[日期]原文`（不带任何分层分类）
- 日期形如 `5.2`（月.日），年份由所在灵感记录文件名（如 `灵感记录26.5.docx` = 2026 年 5 月）提供。
- 标签位允许空位，形如 `[法][文化//经济学/文旅消费]`（圈层留空）。

## 7. 边界

- 《个人认知档案.md》是协作背景，不是观点来源。
- 观点库内容由系统维护；用户的修改意见经 Web 界面 + 后端事务执行，不直接改数据。
