每次版本发布经用户确认后，清空开发版 `backend/data` 的使用痕迹（inspiration.db、*.bak-*、*.done、desktop.log），开发版始终保持零使用痕迹供审查。安装版数据在 `%LOCALAPPDATA%\InspirationSpace\data`，与此互不影响；开发版（uvicorn 8000）与安装版（InspirationSpace.exe）同占 8000 端口，不能同时运行。

### G7. 运行产物不入库（2026-10-17，A，生效）

desktop.log 已移出 git 跟踪；`.gitignore` 覆盖 `*.db`、`*.db.bak-*`、`.env`、构建产物等。任何运行期产生的文件默认不入版本库。

### G8. 界面文本不使用括号解释（2026-10-15，A，生效）

非必要不使用括号作解释性注释。白名单：密码位数提示、标题（中文）/（英文）、（留空）选项、（环境变量）角标、动态数据占位（如 item(s)、{n} 条）。

### G9. 原生双语（2026-10-10，A，生效）

内容被系统接收的那一刻即生成中英双版本存储，原文按**实际语言**标记 original_lang（用户输入按用户发言语言、AI 产出按其回复实际语言，而非界面语言）；系统内部传递一律双语；展示不产生临时翻译。AI 回复语言跟随界面语言选项，与用户发言语言无关。

### G10. 数据差异下结论前先问用户（2026-09-27，B，生效）

验收中发现数据与预期不符时，先向用户求证再处置，不凭间接证据归因。来源：MVP-5 验收时误把用户主动删除的 #2 当作数据事故"恢复"，经澄清后重新删除（详见 docs/05）。

## 二、产品与技术决策（D 系列）

### D1. 规则优先级

用户决策 > 《灵感空间_v2_软件设计说明书》 > 原系统《系统规范》。原系统规范是业务语义参考，不必完全遵守。

### D2. 技术栈：精简版

SQLite + FastAPI + SQLAlchemy + Vite/React/Tailwind SPA + SSE + 简单密码 Session 认证；不引入 PostgreSQL/Redis/Celery/pgvector/MinIO/Docker。任务调度预留进程内方案（APScheduler），一阶段不启用。依据：单用户、本机运行、观点百级数据量。

### D3. 取消定时摄取，输入双通道

- **主通道**：界面直接录入，立即进入待审队列；
- **辅通道**：上传外部 docx，AI 拆解归纳为逐条灵感入队；
- 不再有系统定时摄取、摄取水位与执行时间记录；
- 原摄取阶段的相似性/再现比对职责，并入审议环节的 AI 分析。

### D4. 术语定义与数据模型归属

- **灵感** = 未经审议的条目（待审队列）；**观点** = 完成审议的条目（观点库）。审议是"灵感 → 观点"的唯一转化通道。
- 待审队列即 inspirations 表，不再另设 review_queue 表，也不存在独立的"灵感记录"对象。每条灵感独立编号；迁移旧数据时逐条重新编号，包括无编号的游离文本（作为一条独立灵感入库）。
- **灵感永久留档**：灵感采纳（含修改后采纳）时才创建 viewpoint，灵感本体必须保留——审议可能修改措辞，灵感原文是修改前的底稿，也是"观点 → 来源灵感"追溯链的起点。留档仅供反查，使用频率低，**前端不设独立的灵感页面**：录入入口内嵌在审议页队列栏与首页，灵感原文在观点详情中查看。

### D5. 碰撞与建构暂缓

碰撞模块、派生观点、世界观建构不属于 v2 一阶段任务，规则存档备查（见 `docs/02`）。原因：原系统中两者从未真实运行，规则未经实践校准。随之一并暂缓的：派生观点状态自动推导、定时任务调度、执行检查页面。

### D6. 认证：简单密码 + Session

按单机应用开发，不引入 JWT/OAuth/权限角色。补充（2026-09-27）：账号通过**首次启动初始化页**创建（`/api/auth/setup`，仅 users 表为空时开放），不再要求用户改 `.env`；`.env` 的 `INSPIRATION_ADMIN_PASSWORD` 仅保留为兼容/找回通道。

### D7. AI 服务：本地 New API 网关

- 接入点：本地 New API（`D:\Bob.Heng\开拓之旅\Newapi`，OpenAI 兼容接口，`http://localhost:3000/v1`），用网关中已有的令牌（令牌存于 New API 的 one-api.db / 后台令牌页，**密钥不入代码库**，运行时从环境变量读取）。
- 网关内的模型与渠道在网关侧管理（本软件不配置模型名，运行时自动取可用模型），无独立 Embedding 渠道——一阶段相似判断全部由 LLM 直接完成，这与精简栈决策一致。
- 依赖前提：New API 需通过 `启动网关.bat` 常驻运行；后端启动时应检测网关可达性并给出明确报错。
- 后端仍按设计说明书 §11.3 实现 LLMProvider 抽象层，New API 只是第一个 Provider，未来可换。

补充（2026-09-27）：AI 服务已支持**界面化配置**（审议工作台右栏"AI 服务设置"），可选服务商预设（NewAPI/OpenAI/DeepSeek/Kimi/智谱/自定义 OpenAI 兼容）、API Key、Base URL（可空）、模型。优先级：界面配置（llm_settings 表）> 环境变量。密钥只回显末 4 位；切换服务商强制重填密钥。

### D8. 审议流程语义：pending ↔ in_review 以"是否已生成 AI 分析"为界（2026-10-03）

- **开会话不改变灵感状态**：未生成 AI 分析的灵感一律为 pending（待审议）；AI 分析生成落库时 pending → in_review（仅此一处转换，讨论消息不影响）。
- **暂缓（defer）= 清空本次审议的全部 AI 产物**：删除该会话的分析（含中英文版，随会话行一并删除）与全部讨论消息，删除会话行，灵感回到 pending，不写决策记录、不产生终态；单事务，失败整体回滚。想保留内容就不点暂缓、晾着不动（实质暂缓）。
- **首页"开始审议"自动生成分析**（URL 带 auto=1）：开会话后若无分析且无讨论消息，自动生成 AI 分析；已有分析或讨论（含断点续聊）不重复生成。审议工作台队列内直接点击条目不触发。
- 随之调整：灵感状态机允许 pending → reviewed / rejected（未经 AI 分析直接决策出队）；defer 的 DecisionOut.session_status 返回 "deleted"。

### D9. 打磨两阶段：提炼 → 打磨 + 全站更名（2026-10-03）

- **阶段模型**：`review_sessions` 新增 `phase`（`distill` 提炼 / `polish` 打磨）。新建会话默认 distill；存量会话由 `ensure_schema_upgrades` 回填 polish（旧式审议一律视为打磨阶段）。另有 `distilled_draft`：提炼收敛出的观点草稿，进入打磨后作为"修改后采纳"的正文候选，灵感原文不动。
- **进入流程**：首页"开始打磨"开会话后，对新会话做一次结构化 AI 判断（该灵感是否已构成观点：观点=可裁决的命题；现象/素材/疑问=否）。已是观点 → 弹窗确认后生成分析并直接进 polish；未成观点或取消 → 留在 distill。队列点击不做判断。
- **提炼阶段**：无分析卡、无决策栏；讨论照常，但 AI 以思考伙伴身份自然提问、引导现象收敛为观点，不暴露引导痕迹。每轮 AI 回复附结构化信号 `{ reply, ready_to_polish, distilled_viewpoint }`，只在后端判定，界面无进度条式引导；`ready_to_polish=true` 时弹窗（附可编辑草稿）确认后转 polish 并生成分析。另保留低调的手动"进入打磨"入口，防止 AI 信号保守导致卡住。
- **打磨阶段**：生成分析 → 讨论（质疑型）→ 决策，维持原逻辑；会话带草稿时分析以草稿正文为对象。
- **移除"否定"按钮**：前端决策栏删除否定（用户可在首页删除灵感替代）；后端保留 reject 兼容存量数据，不改历史。
- **更名**（只改 `frontend/src/i18n.jsx` STRINGS 键值，不改键名）：审议（动作）→ 打磨 / Polish；审议工作台 → 他山坊 / Whetstone；观点库 → 集思录 / Anthology。页头在他山坊、集思录两页加 slogan（首页不加）；登录页、浏览器标题、安装包产品名仍叫"灵感空间"。
- **随之调整**：首页"开始打磨"（auto=1）不再直接自动生成分析（D8 的该条被本流程取代），改为先判断再经用户确认生成；pending → in_review 仍以"分析落库"为界，提炼期灵感保持 pending。

### D10. 以观点为中心的存储与生命周期（2026-10-03，取代 D8/D9 中冲突部分）

- **录入即建观点**：首页录入灵感（含 docx 导入确认）时，同事务复制内容创建一条 `status='draft'` 的观点（`source_inspiration_id` 关联）。他山坊全程操作观点：队列、当前卡、讨论、分析、关联观点全部来自 viewpoints 表；草稿观点在集思录隐藏，采纳（accepted）后可见。不再有单独的"打磨中的观点"草稿字段（`review_sessions.distilled_draft` 删除，工作稿即观点正文）。
- **观点状态机只有两态**：`draft`（他山坊）↔ `accepted`（集思录）。悬置、否定从系统整体删除；合并、拆分删除；操作留痕（viewpoint_events）删除（打磨记录 review_sessions/messages/decisions 保留）。冲突关系只建行、不再联动任何状态——"否定"的出口改为：集思录详情「撤销」打回他山坊重新讨论；讨论不出结果则从首页删除灵感（级联删除观点）。
- **灵感无状态机**：`inspirations.status` 删除。首页展示态由关联观点推导（draft=打磨中 / accepted=已入库）。已入库（accepted）的灵感**不可编辑、不可删除**（409 adopted_locked）；须先在集思录撤回。编辑灵感会同步观点正文并把会话重置到提炼最开始（清空讨论与分析，弹窗确认）；删除灵感级联删除观点、会话、消息、决策、关系（弹窗确认）。
- **撤销体系（只删不回，不跨阶段，无需快照）**：`review_messages` 带 `phase`。决策栏在提炼与打磨阶段都呈现：提炼仅「撤销」，打磨为「撤销+采纳」。单击撤销=删当前阶段最后一轮（AI 回复连同其用户提问；落单消息单删），多次点击删完打磨对话后停在提炼最后一步，不恢复任何已删内容（含重新生成删掉的）；长按 3 秒=阶段回退（弹窗确认）：polish→distill（删分析与打磨消息，正文不动）或 distill→重置（清空讨论、正文恢复灵感原文）。「重新生成」分析（弹窗确认）= 删打磨阶段全部消息后重新生成 + 新的打磨衔接首问。
- **采纳只有一个动作**：去掉直接采纳与暂缓，「修改后采纳」更名「采纳」：正文预填观点工作稿可改；标题在打开对话框时由 AI 生成（原生双语），可直接在对话框修改；提交事务=改正文（重新双语化）+写标题+分层标签+建关系（不联动状态）+记决策+会话 completed+观点转 accepted。**观点标题生命周期**：创建观点时沿用灵感标题（灵感标题本身不改动）→ 提炼进打磨时按观点正文自动重新生成一次（进入/收敛弹窗中简要说明）→ 采纳对话框确认（可改）→ 采纳后集思录详情可改（均原生双语）。灵感标题录入时 AI 生成、首页修改，两者自此解耦。启动对账不为草稿观点补标题。
- **撤回（集思录详情「撤销」，弹窗确认）**：accepted→draft，该观点最近的 completed 会话重开为 active（phase=polish，分析与讨论原样保留，即"打磨环节的最后状态"），该会话的 accept 决策行删除（决策随撤回作废）。撤回后灵感恢复可编辑/可删除。
- **统一展示编号**：全站同一对象只显示一个号——**来源灵感编号**（`viewpoints.source_inspiration_id`，无来源时兜底观点 id）。首页/他山坊队列/会话卡/决策栏/决策通知/集思录表格卡片分类详情关系全部统一；内部关联（会话、关系、决策）仍用观点 id。背景：旧库两表编号本已交叉，迁移后 draft 段观感错位一位；从零使用时两表 id 因同事务双写+对称级联删除而天然对齐，但这是涌现性质不作依赖。
- **随之失效**：D8 全部（灵感状态机、暂缓语义、pending↔in_review 边界）；D9 中 distilled_draft、"开始打磨 judging 灵感"改为判断观点正文（机制保留）；首页按钮改「录入灵感」；他山坊 URL 参数为 `viewpoint`。
- **数据迁移**（ensure_schema_upgrades）：消息补 phase（存量=polish）；无观点灵感（含历史 rejected）补建 draft 观点；review_sessions 整表重建为 viewpoint_id 主关联；inspirations 删 status 列；DROP viewpoint_events；viewpoints 补 is_viewpoint 列。幂等，已在真实库副本三跑验证。
- **补充（R5）**：① 阶段徽标——他山坊队列与首页灵感条目按观点会话阶段显示「提炼中」（浅金）/「打磨中」（深金），两页同一组件、转阶段与撤销后实时刷新；② 观点判断前置——`viewpoints.is_viewpoint` 在录入（含 docx 导入）时由 AI 判定落库（失败置 NULL，不阻断录入），编辑内容变化时重判；任何入口的新会话（含队列直接点击）按该标志弹"已构成观点，跳过提炼"进入弹窗，NULL 走 live 判断兜底；③ 撤销地板——跳过提炼的观点（is_viewpoint=true 且无提炼消息）undo-phase 409 undo_floor，撤销到打磨开始为止；④ 集思录三视图编号下方渲染冲突四芒星标记（黑描边红填充星+红色对方编号，数据为 `conflict_with` 展示编号列表）；⑤ 首页灵感客户端分页（每页 10 条，按钮+页码输入，筛选/搜索重置页码）；⑥ 仅改来源日期不重置会话且前端不再弹窗；⑦ 页头 slogan 字号 text-base。
